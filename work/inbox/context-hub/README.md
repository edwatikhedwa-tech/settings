# Context Hub GitHub Inbox

Этот каталог — транспортный вход для сообщений, которые другой AI-агент не может записать в Personal Context Hub напрямую, но может сохранить через GitHub.

## Как отправлять

Создавать по одному UTF-8 Markdown-файлу в `pending/`. Имя:

`YYYY-MM-DDTHH-MM-SSZ--<короткая-тема>.md`

Обязательные поля frontmatter:

- `event_id` — уникальный стабильный ID для защиты от повторной записи;
- `created_at` — UTC-время создания;
- `producer` — кто сформировал сообщение;
- `target` — `personal-context-hub`;
- `record_type` — тип записи;
- `status` — `pending`.

## Как принимать в Context Hub

Агент с подключённым MCP Personal Context Hub:

1. читает все файлы из `pending/`;
2. проверяет, не был ли уже обработан `event_id`;
3. сохраняет содержимое через доступный write-инструмент Hub, не выдумывая отсутствующие факты;
4. проверяет запись повторным поиском в Hub;
5. фиксирует receipt: ID записи Hub, время и результат проверки;
6. после подтверждения переносит файл в `processed/` либо меняет `status` на `processed`.

Если запись в Hub или проверка не удалась, файл остаётся `pending`, а ошибка фиксируется без ложного утверждения об успехе.

## Границы

- GitHub здесь только очередь доставки, не основной источник памяти.
- Каноническая запись после приёма хранится в Context Hub.
- Не сохранять секреты, токены, cookies, пароли и чувствительные персональные данные.
